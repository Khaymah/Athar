# ADR-0001: أداة التقييم مبنية على Python + mini-swe-agent + SWE-bench

**التاريخ:** 2026-11-03 · **الحالة:** مقبول

## السياق

محتاجين نشغّل coding agents على تاسكات SWE-bench Verified بصيغ لغوية مختلفة ونقيّم الـ patches بالاختبارات المخفية، بأقل تكلفة ووقت عشان نثبت القيمة قبل أي استثمار أكبر.

## القرار

- **Python** بدل الـ stack الافتراضي (Bun/TS)، لأن أداة التقييم الرسمية `swebench` و`mini-swe-agent` الاتنين Python. إعادة كتابتهم = أسابيع، وبتصعّب على الباحثين إنهم يكرروا النتايج.
- **mini-swe-agent** كـ scaffold موحّد لكل الموديلات (مسار "الموديل" في الورقة). نفس الـ system prompt الإنجليزي لكل الصيغ؛ اللي بيتغير نص التاسك بس.
- **OpenRouter** كبوابة واحدة لكل الموديلات: مفتاح واحد، والتكلفة بترجع من الـ API نفسه (مش تقدير).
- **Images من GHCR (Epoch AI)** بدل Docker Hub: أصغر، ومش بتتقفل بـ rate limit المجهول (اتقفلنا فعلاً بـ 429 من Docker Hub).
- **التشغيل task-major**: image واحدة على الديسك في المرة، وتتمسح بعد ما خلاياها تخلص.

## المحاور الحاكمة

| المحور | القرار |
|---|---|
| صحة القياس | التصميم المتزاوج (نفس التاسك بكل الصيغ) + المرفقات بايت-بايت متطابقة + `gold`/`empty` كفحص سلامة |
| التكلفة | موديل frontier + موديل رخيص؛ معايرة على ٥ تاسكات قبل الـ Pilot الكامل |
| قابلية التكرار | كل خلية محفوظة: النص اللي الـ agent شافه + الـ trajectory + الـ patch + log التقييم |

**بنضحّي بـ** "مسار المنتج" (Claude Code / Cursor كما هي) **لصالح** مقارنة عادلة ورخيصة بين الموديلات، لأن هدف المرحلة دي إثبات وجود الأثر، مش ترتيب المنتجات.

## العواقب

- الأثر المقاس هو أثر اللغة على الموديل تحت scaffold بسيط؛ ممكن يختلف عن المنتجات التجارية اللي ليها system prompts أطول.
- لو الـ Pilot نجح، نضيف مسار المنتج كمرحلة تانية.
